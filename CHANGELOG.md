# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
While the version is 0.x, minor versions may contain breaking changes; they are
listed under a "Breaking" heading.

## [Unreleased]

## [0.2.0] - 2026-10-17

The first release without a preview suffix. It adds Unity WebGL support through a new Unity package; the public API of the NuGet packages is unchanged. The LRS still passes both ADL conformance batteries in full on SQLite and PostgreSQL (xAPI 2.0.0: 1435 of 1435, 1.0.3: 1365 of 1365), the solution has about 5,300 tests, and the 11 Unity tests pass in the editor, in a Linux IL2CPP player and, locally, in WebGL.

### Added

- `samples/LrsHost` and the `xapi-lrs` image: `LrsHost:AllowedOrigins` (`LrsHost__AllowedOrigins` in Docker) turns on CORS for the listed origins, so xAPI content in a browser on another origin can use the LRS. It is off by default.
- `tests/Unity`: Unity 6.3 tests of `Xapi.Core`, `Xapi.Client` and `Xapi.Client.Outbox`, installed with NuGetForUnity, that run in the editor, in IL2CPP players and in WebGL; CI runs them on Linux against the packages packed from the commit, and `tests/Unity/WebGL` runs a WebGL build in headless Chromium. See [docs/unity.md](docs/unity.md).
- A Unity package, `io.github.nurullahturkoglu.xapi.unity` in `src/Xapi.Unity`, installed from git: `UnityWebRequestHandler`, an `HttpMessageHandler` that sends requests with `UnityWebRequest`, so `XapiClient` works in WebGL players, where `HttpClient`'s default handler sends nothing.

### Fixed

- `FileOutboxStore.OpenAsync` never completed in Unity WebGL players when the store already had a journal, because the netstandard2.0 build read it with asynchronous file I/O, which needs the thread pool. That build now reads the journal synchronously; the net10.0 build is unchanged.

## [0.1.0-preview.1] - 2026-10-17

The first preview of all six packages. The LRS passes both ADL conformance batteries in full on SQLite and PostgreSQL (xAPI 2.0.0: 1435 of 1435, 1.0.3: 1365 of 1365), and the solution has about 5,300 tests.

### Added

- `Xapi.Core`: immutable models for xAPI 1.0.3 and 2.0.0 (IEEE 9274.1.1), strict and lenient JSON reading with all errors reported by JSON path, JSON writing in exact, ids and canonical formats, statement and batch validation, and statement equivalence as defined by the standard. Targets netstandard2.0 and net10.0.
- The 1,922 statement cases generated by the ADL LRS conformance test suite templates (950 for 1.0.3, 972 for 2.0.0) run as unit tests against the parser.
- CI runs both ADL conformance batteries against lrsql to keep the conformance pipeline itself tested.
- `Xapi.Client`: an `HttpClient`-based client for any xAPI 1.0.3 or 2.0.0 LRS. Covers statements (save, batch, get, voided, query with `more` paging, void), state, activity and agent profile documents with ETag preconditions, agents, activities and about. Sends and reads attachments as multipart/mixed, negotiates the version through `/about` when none is set, and maps 409 and 412 to typed exceptions. `AddXapiClient` registers it with `IHttpClientFactory` on net10.0. Targets netstandard2.0 and net10.0 and is Native AOT compatible.
- `Xapi.Client.Outbox`: a durable outbox for statements. `StatementOutbox` assigns ids before storing, so resends are idempotent, and delivers in order and in batches, with exponential backoff and jitter for transient errors, `Retry-After`, bisection of rejected batches, 409 resolution through `StatementEquivalence`, a pause on 401 and 403, and inspectable, requeueable dead letters. `FileOutboxStore` keeps an append-only, checksummed journal that survives a process killed mid-write; `InMemoryOutboxStore` is for tests. Runs with `FlushAsync`, with a background loop that needs no host, or as a hosted service through `AddXapiClient(...).AddOutbox(...)` on net10.0. Targets netstandard2.0 and net10.0. See [docs/outbox.md](docs/outbox.md).
- `Xapi.Lrs`: an LRS that runs inside an ASP.NET Core app (`AddXapiLrs`, `MapXapiLrs`). It negotiates xAPI 1.0.3 and 2.0, authenticates with Basic credentials (PBKDF2-hashed) or a delegated ASP.NET Core scheme, applies the xAPI scopes, and serves About and the Statement Resource write path: PUT and POST with strict validation, conflict detection by statement equivalence, voiding, one transaction per batch, and GET of single statements by `statementId` or `voidedStatementId`. Statement queries support every filter of the standard (including `related_agents`, `related_activities` and matches through StatementRefs, with voided statements left out), the `exact`, `ids` and `canonical` formats with Accept-Language, stateless `more` paging keyed on the stored order (`MaxStatementsPerPage`), Last-Modified and X-Experience-API-Consistent-Through. xAPI 1.0.x requests may use the Alternate Request Syntax. It also serves the State, Activity Profile and Agent Profile Resources: GET of one document or of the ids (with `since`), PUT, POST with JSON merge, DELETE of one document or of all state (with or without a registration), HEAD, SHA-1 ETags and `Last-Modified`, `If-Match` / `If-None-Match` checked atomically with the write, and the 409 and 400 rules for missing preconditions that differ between 1.0.3 and 2.0. Documents are limited to `MaxDocumentBytes` (1 MiB by default). The Agents and Activities Resources return a Person and the canonical Activity definition. Targets net10.0.
- `Xapi.Lrs`: statement attachments. PUT and POST accept multipart/mixed, match parts to Attachment objects by SHA-2 (one part may serve several statements of a batch) and reject missing, extra or mismatching parts; data is stored once per SHA-2 and limited by `MaxAttachmentBytes` (50 MiB per request by default, 413 above it). `attachments=true` returns the statements with their attachment data as multipart/mixed, for single statements and queries.
- `Xapi.Lrs`: signed statements are checked as IEEE 9274.1.1, 4.2.6 requires: an RS256, RS384 or RS512 JWS whose payload is equivalent to the statement (durations to 0.01 second), verified with the `x5c` certificate when there is one. Malformed signatures get 400. See [docs/signatures.md](docs/signatures.md).
- `Xapi.Client`: `StatementSigner` signs a statement with an RSA key and an optional certificate chain, and returns the statement with its signature attachment and the JWS to send with `SaveStatementAsync`.
- `Xapi.Lrs.Sqlite` and `Xapi.Lrs.PostgreSql`: EF Core storage with migrations (`UseSqlite`, `UsePostgreSql`, `MigrateOnStartup`). The storage extension points (`IStatementStore`, `IDocumentStore`) are marked experimental (`XAPI0001`).
- `samples/LrsHost`: a standalone LRS on SQLite or PostgreSQL, used as the target of the conformance runs. CI runs both batteries against it on both databases. `samples/LrsHost/Dockerfile` builds it into a non-root image that stores SQLite data in `/data` and will not start without credentials; CI builds and checks the image.
- Samples `EmbedInAspNetCore` and `FakeLrsInTests`, and guides in docs/ (getting started, client, LRS, versions, migrating from TinCan.NET, conformance) whose C# blocks are compiled and checked by `tests/Xapi.Documentation.Tests`.
- `benchmarks/Xapi.Benchmarks`: BenchmarkDotNet benchmarks for statement parsing, writing, validation and equivalence, outbox enqueueing, and the LRS statement endpoints on SQLite and PostgreSQL, with measured results in [docs/benchmarks.md](docs/benchmarks.md).
- A documentation site built with docfx from the guides and the XML docs, deployed to GitHub Pages from `main`: https://nurullahturkoglu.github.io/xapi-dotnet/
- `Xapi.Lrs`: `MaxStatementsPerBatch` (1,000 by default) limits the statements in one POST; larger batches get 413 before they are parsed.
- `Xapi.Lrs`: `MigrateXapiLrsDatabaseAsync()` on the app's `IServiceProvider` applies the database migrations as a separate deployment step, so migrating no longer needs the experimental `XapiLrsDbContext`.
- `Xapi.Core`: `XapiErrorCodes.AttachmentPayloadMissing` and `XapiErrorCodes.AttachmentPayloadUnreferenced`, the codes `Xapi.Client` and `Xapi.Client.Outbox` report for attachment data. The values are unchanged. `XapiError.Path` documents that the path of `attachment.payload.unreferenced` is an index into the attachment data (`attachments[0]`), not a JSON path.
- `Xapi.Lrs`: `AddXapiLrs(configuration, configure)` binds the options from a configuration section, credentials included (`Lrs:Credentials:0:Key`, `:Secret`, `:Scopes:0`), and then runs `configure` for what only code can set. Scopes are xAPI scope names; a misspelt key, an incomplete credential, an unknown scope or a value out of range stops the host at startup, and no message contains a secret. `samples/LrsHost` reads its options this way, so it accepts more than one credential. See [Options from configuration](docs/lrs.md#options-from-configuration).
- `Xapi.Lrs`: metrics on the `Xapi.Lrs` meter (`xapi.lrs.request.duration`, `xapi.lrs.errors`, `xapi.lrs.statements.stored`) and activities on the `Xapi.Lrs` activity source for storing and querying statements and writing documents, with `System.Diagnostics` and no OpenTelemetry dependency. Tags never carry agents, IRIs, ids or credential keys. The names are constants of `XapiLrsDiagnostics`. See [Metrics and traces](docs/lrs.md#metrics-and-traces).
- `Xapi.Lrs`: `AddXapiLrsHealthCheck()` reports whether the database can be reached and is migrated. `samples/LrsHost` serves it at `/health`.
- `Xapi.Client` and `Xapi.Client.Outbox`: metrics on the `Xapi.Client` meter: statements sent, retried and dead-lettered, and the statements pending in outboxes. The netstandard2.0 build of `Xapi.Client` now depends on `System.Diagnostics.DiagnosticSource`.
- Releases publish the `samples/LrsHost` image to ghcr.io as `ghcr.io/nurullahturkoglu/xapi-lrs`, for linux/amd64 and linux/arm64, tagged with the version and, for releases that are not previews, `latest`, with a signed build provenance attestation. See [Running the sample LRS in Docker](docs/lrs.md#running-the-sample-lrs-in-docker).
- The packages have an icon, which the documentation site also uses as its logo and favicon.

### Changed

- `Xapi.Core`: reading a statement allocates about a quarter of what it did (5.2 KB instead of 19.7 KB for a 1 KB statement in strict mode) and takes about 40% less time. JSON paths are formatted only when an error is reported, and known property names are matched without creating strings or a hash set per object. Errors are unchanged. See [docs/benchmarks.md](docs/benchmarks.md).
- `Xapi.Lrs`: statement queries read each filter's own index (verb, registration, and one range per agent or activity usage, plus StatementRef matches) newest first and only as far as one page, instead of testing every statement. At 100,000 statements a verb with no matches takes 0.22 ms instead of 70 ms on SQLite and 0.84 ms instead of 52 ms on PostgreSQL, and an `agent` query with `related_agents` 2.3 ms instead of 581 ms and 5.9 ms instead of 15 ms.
- `Xapi.Lrs`: on SQLite, the matches through StatementRefs start from the filter's index when it matches fewer statements than there are StatementRefs, instead of looking up the target of every StatementRef. At 100,000 statements of which 10% are StatementRefs, a verb with no matches takes 0.42 ms instead of 23 ms and an `agent` query with `related_agents` 4.1 ms instead of 65 ms. PostgreSQL already chose this from its statistics. See [docs/benchmarks.md](docs/benchmarks.md#statement-queries-with-statementrefs).
- `Xapi.Lrs`: `attachments=true` responses are streamed, reading the data of one attachment at a time, and HEAD reads none. `IStatementStore.GetAttachmentsAsync` is replaced by `GetAttachmentSummariesAsync` and `GetAttachmentContentAsync`.
- `Xapi.Lrs.Sqlite` and `Xapi.Lrs.PostgreSql` depend on the exact version of `Xapi.Lrs` they were built with (`[x.y.z]`), because they use its experimental storage types.
- `Xapi.Lrs`: the storage API marked `XAPI0001` stays experimental after 1.0 until it is declared stable, and is not covered by semantic versioning until then. The `XAPI0001` error links to [Experimental storage API](docs/lrs.md#experimental-storage-api).
- Each package has its own NuGet tags on top of the shared ones (`lrs` and `learning-record-store` only on the LRS packages), and the package release notes link to this changelog.
- `Xapi.Lrs`: the options are validated when the host starts (`ValidateOnStart`). A host with no credentials and no `AuthenticationScheme`, an empty or built-in (`XapiBasic`) scheme name, an empty `ScopeClaimType`, a missing or relative `AuthorityHomePage`, a size or count limit out of range (`MaxDocumentBytes` below 1 included), or an invalid credential (missing key or secret, a key with a colon or used twice, no scope or an unknown one) now fails to start with an `OptionsValidationException` that lists every problem, instead of starting with settings under which requests cannot be authenticated. Credentials are named by index and key, never by secret.
- The netstandard2.0 builds of `Xapi.Core`, `Xapi.Client` and `Xapi.Client.Outbox` depend on the lowest versions that have the APIs they use and no known vulnerability, instead of the newest: System.Text.Json 10.0.0, Microsoft.Bcl.AsyncInterfaces 10.0.0, Microsoft.Bcl.TimeProvider 8.0.1 and System.Diagnostics.DiagnosticSource 7.0.0 (were 10.0.13), so a .NET Framework or Unity app that already uses one of them does not have to move it to the newest release.
- Each package has its own short README on NuGet, with a usage example, its target frameworks and links to the documentation, instead of the repository README.

### Fixed

- `Xapi.Lrs.Sqlite`: a write that timed out waiting for the database lock (`SQLITE_BUSY`) is no longer retried, which made a request wait about 4 minutes before it failed.
- `Xapi.Lrs.Sqlite`: read-only connections no longer try to switch the database to WAL mode, so the health check reports the pending migrations of a database that is not in WAL mode yet instead of reporting it unreachable.

### Security

- `Xapi.Lrs`: statement and document writes set the server's request body limit from the LRS options, so `MaxAttachmentBytes` and `MaxDocumentBytes` above Kestrel's default of about 28.6 MiB now take effect. The new `MaxStatementBytes` (16 MiB) limits the statement JSON of one request, which before was bounded only by the server.
- `Xapi.Lrs`: an unknown Basic key now costs the same PBKDF2 check as a wrong secret, so response times no longer tell which keys exist.
- `Xapi.Lrs`: every response has `X-Content-Type-Options: nosniff`, and documents that are not JSON are served with `Content-Disposition: attachment` and a sandboxing `Content-Security-Policy`, so stored HTML or SVG cannot run on the origin of the app that hosts the LRS.
- `Xapi.Lrs`: on PostgreSQL, IRIs, agent identifiers and document ids too long for an index get 400 instead of 500.
- `Xapi.Lrs`: the form of an Alternate Request Syntax request, which is read before the request is authenticated, is limited to `MaxAlternateRequestBytes` (1 MiB by default) instead of the server's request body limit; larger forms get 413.
- docs/lrs.md covers rate limiting against secret guessing, CORS for browser clients, and keeping agent email addresses out of request logs.
