# Changelog

All notable changes to this project are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
While the version is 0.x, minor versions may contain breaking changes; they are
listed under a "Breaking" heading.

## [Unreleased]

### Added

- `Xapi.Core`: immutable models for xAPI 1.0.3 and 2.0.0 (IEEE 9274.1.1), strict and lenient JSON reading with all errors reported by JSON path, JSON writing in exact, ids and canonical formats, statement and batch validation, and statement equivalence as defined by the standard. Targets netstandard2.0 and net10.0.
- The 1,922 statement cases generated by the ADL LRS conformance test suite templates (950 for 1.0.3, 972 for 2.0.0) run as unit tests against the parser.
- CI runs both ADL conformance batteries against lrsql to keep the conformance pipeline itself tested.
- `Xapi.Client`: an `HttpClient`-based client for any xAPI 1.0.3 or 2.0.0 LRS. Covers statements (save, batch, get, voided, query with `more` paging, void), state, activity and agent profile documents with ETag preconditions, agents, activities and about. Sends and reads attachments as multipart/mixed, negotiates the version through `/about` when none is set, and maps 409 and 412 to typed exceptions. `AddXapiClient` registers it with `IHttpClientFactory` on net10.0. Targets netstandard2.0 and net10.0 and is Native AOT compatible.
- `Xapi.Client.Outbox`: a durable outbox for statements. `StatementOutbox` assigns ids before storing, so resends are idempotent, and delivers in order and in batches, with exponential backoff and jitter for transient errors, `Retry-After`, bisection of rejected batches, 409 resolution through `StatementEquivalence`, a pause on 401 and 403, and inspectable, requeueable dead letters. `FileOutboxStore` keeps an append-only, checksummed journal that survives a process killed mid-write; `InMemoryOutboxStore` is for tests. Runs with `FlushAsync`, with a background loop that needs no host, or as a hosted service through `AddXapiOutbox` on net10.0. Targets netstandard2.0 and net10.0. See [docs/outbox.md](docs/outbox.md).
- `Xapi.Lrs`: an LRS that runs inside an ASP.NET Core app (`AddXapiLrs`, `MapXapiLrs`). It negotiates xAPI 1.0.3 and 2.0, authenticates with Basic credentials (PBKDF2-hashed) or a delegated ASP.NET Core scheme, applies the xAPI scopes, and serves About and the Statement Resource write path: PUT and POST with strict validation, conflict detection by statement equivalence, voiding, one transaction per batch, and GET of single statements by `statementId` or `voidedStatementId`. Statement queries support every filter of the standard (including `related_agents`, `related_activities` and matches through StatementRefs, with voided statements left out), the `exact`, `ids` and `canonical` formats with Accept-Language, stateless `more` paging keyed on the stored order (`MaxStatementsPerPage`), Last-Modified and X-Experience-API-Consistent-Through. xAPI 1.0.x requests may use the Alternate Request Syntax. It also serves the State, Activity Profile and Agent Profile Resources: GET of one document or of the ids (with `since`), PUT, POST with JSON merge, DELETE of one document or of all state (with or without a registration), HEAD, SHA-1 ETags and `Last-Modified`, `If-Match` / `If-None-Match` checked atomically with the write, and the 409 and 400 rules for missing preconditions that differ between 1.0.3 and 2.0. Documents are limited to `MaxDocumentBytes` (1 MiB by default). The Agents and Activities Resources return a Person and the canonical Activity definition. Targets net10.0.
- `Xapi.Lrs`: statement attachments. PUT and POST accept multipart/mixed, match parts to Attachment objects by SHA-2 (one part may serve several statements of a batch) and reject missing, extra or mismatching parts; data is stored once per SHA-2 and limited by `MaxAttachmentBytes` (50 MiB per request by default, 413 above it). `attachments=true` returns the statements with their attachment data as multipart/mixed, for single statements and queries.
- `Xapi.Lrs`: signed statements are checked as IEEE 9274.1.1, 4.2.6 requires: an RS256, RS384 or RS512 JWS whose payload is equivalent to the statement (durations to 0.01 second), verified with the `x5c` certificate when there is one. Malformed signatures get 400. See [docs/signatures.md](docs/signatures.md).
- `Xapi.Client`: `StatementSigner` signs a statement with an RSA key and an optional certificate chain, and returns the statement with its signature attachment and the JWS to send with `SaveStatementAsync`.
- `Xapi.Lrs.Sqlite` and `Xapi.Lrs.PostgreSql`: EF Core storage with migrations (`UseSqlite`, `UsePostgreSql`, `MigrateOnStartup`). The storage extension points (`IStatementStore`, `IDocumentStore`) are marked experimental (`XAPI0001`).
- `samples/LrsHost`: a standalone LRS on SQLite or PostgreSQL, used as the target of the conformance runs. CI runs both batteries against it on both databases. `samples/LrsHost/Dockerfile` builds it into a non-root image that stores SQLite data in `/data` and will not start without credentials; CI builds and checks the image but does not publish it.
- Samples `EmbedInAspNetCore` and `FakeLrsInTests`, and guides in docs/ (getting started, client, LRS, versions, migrating from TinCan.NET, conformance) whose C# blocks are compiled and checked by `tests/Xapi.Documentation.Tests`.
- `benchmarks/Xapi.Benchmarks`: BenchmarkDotNet benchmarks for statement parsing, writing, validation and equivalence, outbox enqueueing, and the LRS statement endpoints on SQLite and PostgreSQL, with measured results in [docs/benchmarks.md](docs/benchmarks.md).
- A documentation site built with docfx from the guides and the XML docs, deployed to GitHub Pages from `main`: https://nurullahturkoglu.github.io/xapi-dotnet/
- `Xapi.Lrs`: `MaxStatementsPerBatch` (1,000 by default) limits the statements in one POST; larger batches get 413 before they are parsed.
- `Xapi.Lrs`: `MigrateXapiLrsDatabaseAsync()` on the app's `IServiceProvider` applies the database migrations as a separate deployment step, so migrating no longer needs the experimental `XapiLrsDbContext`.

### Changed

- `Xapi.Core`: reading a statement allocates about a quarter of what it did (5.2 KB instead of 19.7 KB for a 1 KB statement in strict mode) and takes about 40% less time. JSON paths are formatted only when an error is reported, and known property names are matched without creating strings or a hash set per object. Errors are unchanged. See [docs/benchmarks.md](docs/benchmarks.md).
- `Xapi.Lrs`: statement queries read each filter's own index (verb, registration, and one range per agent or activity usage, plus StatementRef matches) newest first and only as far as one page, instead of testing every statement. At 100,000 statements a verb with no matches takes 0.22 ms instead of 70 ms on SQLite and 0.84 ms instead of 52 ms on PostgreSQL, and an `agent` query with `related_agents` 2.3 ms instead of 581 ms and 5.9 ms instead of 15 ms.
- `Xapi.Lrs`: `attachments=true` responses are streamed, reading the data of one attachment at a time, and HEAD reads none. `IStatementStore.GetAttachmentsAsync` is replaced by `GetAttachmentSummariesAsync` and `GetAttachmentContentAsync`.

### Fixed

- `Xapi.Lrs.Sqlite`: a write that timed out waiting for the database lock (`SQLITE_BUSY`) is no longer retried, which made a request wait about 4 minutes before it failed.

### Security

- `Xapi.Lrs`: statement and document writes set the server's request body limit from the LRS options, so `MaxAttachmentBytes` and `MaxDocumentBytes` above Kestrel's default of about 28.6 MiB now take effect. The new `MaxStatementBytes` (16 MiB) limits the statement JSON of one request, which before was bounded only by the server.
- `Xapi.Lrs`: an unknown Basic key now costs the same PBKDF2 check as a wrong secret, so response times no longer tell which keys exist.
- `Xapi.Lrs`: every response has `X-Content-Type-Options: nosniff`, and documents that are not JSON are served with `Content-Disposition: attachment` and a sandboxing `Content-Security-Policy`, so stored HTML or SVG cannot run on the origin of the app that hosts the LRS.
- `Xapi.Lrs`: on PostgreSQL, IRIs, agent identifiers and document ids too long for an index get 400 instead of 500.
- `Xapi.Lrs`: the form of an Alternate Request Syntax request, which is read before the request is authenticated, is limited to `MaxAlternateRequestBytes` (1 MiB by default) instead of the server's request body limit; larger forms get 413.
- docs/lrs.md covers rate limiting against secret guessing, CORS for browser clients, and keeping agent email addresses out of request logs.
