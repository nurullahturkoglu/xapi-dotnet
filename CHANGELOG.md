## [Unreleased]

### Added

- `Xapi.Core`: immutable models for xAPI 1.0.3 and 2.0.0 (IEEE 9274.1.1), strict and lenient JSON reading with all errors reported by JSON path, JSON writing in exact, ids and canonical formats, statement and batch validation, and statement equivalence as defined by the standard. Targets netstandard2.0 and net10.0.
- The 1,922 statement cases generated by the ADL LRS conformance test suite templates (950 for 1.0.3, 972 for 2.0.0) run as unit tests against the parser.
- CI runs both ADL conformance batteries against lrsql to keep the conformance pipeline itself tested.
- `Xapi.Client`: an `HttpClient`-based client for any xAPI 1.0.3 or 2.0.0 LRS. Covers statements (save, batch, get, voided, query with `more` paging, void), state, activity and agent profile documents with ETag preconditions, agents, activities and about. Sends and reads attachments as multipart/mixed, negotiates the version through `/about` when none is set, and maps 409 and 412 to typed exceptions. `AddXapiClient` registers it with `IHttpClientFactory` on net10.0. Targets netstandard2.0 and net10.0 and is Native AOT compatible.
- `Xapi.Lrs`: an LRS that runs inside an ASP.NET Core app (`AddXapiLrs`, `MapXapiLrs`). It negotiates xAPI 1.0.3 and 2.0, authenticates with Basic credentials (PBKDF2-hashed) or a delegated ASP.NET Core scheme, applies the xAPI scopes, and serves About and the Statement Resource write path: PUT and POST with strict validation, conflict detection by statement equivalence, voiding, one transaction per batch, and GET of single statements by `statementId` or `voidedStatementId`. Statement queries support every filter of the standard (including `related_agents`, `related_activities` and matches through StatementRefs, with voided statements left out), the `exact`, `ids` and `canonical` formats with Accept-Language, stateless `more` paging keyed on the stored order (`MaxStatementsPerPage`), Last-Modified and X-Experience-API-Consistent-Through. It also serves the State, Activity Profile and Agent Profile Resources: GET of one document or of the ids (with `since`), PUT, POST with JSON merge, DELETE of one document or of all state (with or without a registration), HEAD, SHA-1 ETags and `Last-Modified`, `If-Match` / `If-None-Match` checked atomically with the write, and the 409 and 400 rules for missing preconditions that differ between 1.0.3 and 2.0. Documents are limited to `MaxDocumentBytes` (1 MiB by default). Agents, Activities and multipart requests are not implemented yet. Targets net10.0.
- `Xapi.Lrs.Sqlite` and `Xapi.Lrs.PostgreSql`: EF Core storage with migrations (`UseSqlite`, `UsePostgreSql`, `MigrateOnStartup`). The storage extension points (`IStatementStore`, `IDocumentStore`) are marked experimental (`XAPI0001`).
- `samples/LrsHost`: a standalone LRS on SQLite or PostgreSQL, used as the target of the conformance runs. CI runs both batteries against it on both databases.
